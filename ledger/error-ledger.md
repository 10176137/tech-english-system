# 个人专属错题本 (Bug Tracker for English) 🐞

> **法则**：不怕犯错，怕的是同一个 Bug 在生产环境跑两次。每次练习中被指出的生硬/中式表达，自动记入此本，定期重温。

---

## 历史修复记录 (Fixed Issues)

### Issue #001: 称呼过于层级化
* ❌ **错误表达**：`Good morning, sir`
* 💡 **根本原因**：把国内对上级或传统客套代入跨国扁平化团队。老外会觉得等级森严、像在军训。
* ✅ **地道修复**：
  * 对全组：`Morning everyone!` / `Morning team!`
  * 对主管/同事：`Morning Alex!`（直接叫名字即可）

---

### Issue #002: 术语错位 (outtime vs timeout)
* ❌ **错误表达**：`due to login outtime`
* 💡 **根本原因**：中式字对字直译“超时”。
* ✅ **地道修复**：
  * 超时统一为：`timeout`
  * 优雅搭配：`the login timeout bug` / `session timeout issue`

---

### Issue #003: 概念混淆 (Backlog vs Blocker)
* ❌ **错误表达**：`there is no backlog`
* 💡 **根本原因**：把“阻塞”记成了“待办池”。*No backlog* 意思是“团队已经没有需求可以做了”。
* ✅ **地道修复**：
  * 阻碍/卡点是：`blocker`
  * 极简脱口而出：`No blockers at the moment.`

---

### Issue #004: 动词缺失 (PR 是名词)
* ❌ **错误表达**：`the code had been PR`
* 💡 **根本原因**：把名词缩写当被动语态动词用。
* ✅ **地道修复**：
  * 我提了 PR：`I've put up a PR.` / `I've opened a PR.`
  * PR 在等待审核：`The PR is up for review.`

---

### Issue #005: 关键动作“对齐/对一下”卡壳
* ❌ **错误表达**：`I need to [blank] with frontend stuff`
* 💡 **根本原因**：找不到“对接口/对需求”的那个灵魂动词。
* ✅ **地道修复**：
  * 核心语块：`sync with [someone] on [something]`
  * 例句：`I need to sync with the frontend team on the API contract.`

---

### Issue #006: 面试动机大忌 (吐槽国内太卷)
* ❌ **错误表达**：*In China it's too competitive / 996, so I want to try going abroad.*
* 💡 **根本原因**：海外面试中抱怨前环境会被判定为缺乏自驱力与负面态度（Red Flag）。
* ✅ **地道修复**：
  * 正面重构：*“I'm looking to step out of my comfort zone and work in a diverse, international team that values engineering autonomy and code quality.”*
